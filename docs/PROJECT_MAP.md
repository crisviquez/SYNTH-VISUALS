# Mapa del repositorio

La estructura está preparada para crecer sin convertir el proyecto en una colección desordenada de carpetas. No todas las carpetas necesitan contenido desde el primer día.

## Carpetas

- `docs/planning/`: definición del proyecto, alcance, requisitos y decisiones de producto.
- `docs/learning/`: ruta de aprendizaje, apuntes y conceptos estudiados.
- `docs/technical/`: arquitectura, decisiones técnicas y notas de compatibilidad.
- `docs/journal/`: registro de avances, dificultades y aprendizajes.
- `docs/research/`: investigación sobre sonido, animación, formatos y referencias técnicas.
- `inspiration/`: moodboard, referencias visuales y análisis de cada referencia.
- `materials/`: materiales propios reutilizables, paletas, fuentes con licencia y recursos de diseño.
- `src/`: código de la aplicación.
- `tests/`: pruebas automatizadas o manuales.
- `experiments/`: prototipos aislados para aprender o probar ideas sin romper la aplicación principal.
- `assets/`: recursos que la aplicación realmente utiliza.
- `showcase/`: capturas, GIFs ligeros, videos de demostración y materiales de presentación.
- `content/`: planificación y guiones de Shorts/Reels sobre el proceso.
- `scripts/`: utilidades de desarrollo o preparación de archivos, si hacen falta.

## Diferencias importantes

- `inspiration/` contiene referencias ajenas que estudias; `materials/` contiene recursos propios o licenciados para uso; `assets/` contiene recursos que la aplicación carga.
- `experiments/` contiene pruebas temporales o educativas; `src/` contiene el código que forma parte de la aplicación.
- `showcase/` contiene resultados seleccionados para mostrar; `exports/` no se versiona por defecto porque puede contener videos pesados.

## Regla práctica

Añade una carpeta cuando exista una necesidad real. Si una carpeta está vacía y todavía no tiene una función clara, puedes dejarla fuera hasta que la necesites.
